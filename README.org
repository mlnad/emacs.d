* Overview
This is a highly customized Emacs configuration designed for efficient coding,
writing, and project management.

** Key Features
- Modular Design: The configuration is organized into logical sections, making
  it easy to navigate and modify.

- Dynamic Code Generation: Org-mode tables and Babel blocks are used to
  dynamically generate Emacs Lisp code, reducing redundancy and improving
  maintainability.

- Extensive Customization: Variables, keybindings, and package configurations
  are tailored to optimize workflows for coding, writing, and project
  management.

- Modern Tools: Integration with modern Emacs packages like Eglot (for LSP),
  Vertico (for completion), and Magit (for version control) ensures a
  cutting-edge development experience.

- Cross-Platform Support: The configuration is designed to work seamlessly
  across different operating systems, with specific adjustments for Windows,
  Linux, and macOS.

** Mono-file
All the configurations for start Emacs is integrated into [[file:init.org][init.org]]. These codes
can be tangled into ~init.el~ and ~early-init.el~ by =org-babel-tangle=.

* Installation
1. Clone this repository:
   #+begin_src shell
   git clone https://github.com/mlnad/moyu-emacs.git ~/.emacs.d
   #+end_src

2. Install dependencies:
   #+begin_src shell
   sudo apt install ripgrep fd-find tree-sitter
   #+end_src

3. Start Emacs - packages will be automatically installed

* Health check
=moyue doctor= verifies that the configuration files are complete and correct:
=init.org= / =init.el= are present, =elpa/= is populated, =.cache/env.el= is
readable Lisp, and the declared fonts are well formed. It runs the checks built
into [[file:bin/moyue.el][bin/moyue.el]] and exits non-zero if any of them fail:
#+begin_src shell
bin/moyue doctor                       # every check
bin/moyue doctor config/emacs-version  # a single check
#+end_src

The unit tests for the =lisp/= helpers and the =bin/commands/= extensions are a
separate concern and run with =moyue test=. With no argument it runs every test
outside the =config/= namespace; a pattern is an ERT selector read as Lisp, so a
regexp needs quotes of its own:
#+begin_src shell
bin/moyue test                        # everything except config/
bin/moyue test '"^treesit-"'          # tests whose name matches a regexp
bin/moyue test config/emacs-version   # one test, by name
#+end_src

* Tree-sitter grammars
Grammar libraries are pinned to exact upstream revisions, compiled into
=~/.emacs.d/.cache/tree-sitter/=, and built from sources kept in
=~/.emacs.d/.cache/tree-sitter/src/<lang>/=.

The cache is searched before =~/.emacs.d/tree-sitter/= and before the system
library directories, so a grammar built there is always the one Emacs uses,
while a grammar that has not been built yet falls back to whatever else
provides it. Nothing ever compiles an upstream default branch on its own:
built-in grammar downloading is switched off, and the revision to build comes
from the pinned manifest in [[file:bin/commands/treesit.el][bin/commands/treesit.el]] -- a command-line
concern, so =init.el= only declares where to look and loads no library.

Because the sources are kept, a grammar can be edited by hand and recompiled.
=moyue treesit build= compiles whatever revision is on disk; it never resets
the checkout. =moyue treesit reset= is what restores the pinned revision.

#+begin_src shell
bin/moyue install --grammars          # check out and build every pinned grammar
bin/moyue treesit status              # pin, source and library state
bin/moyue treesit sync                # fetch the pins, then build (network)
bin/moyue treesit build bash python   # rebuild selected grammars (offline)
bin/moyue treesit update --write      # move the pins to newer releases
bin/moyue treesit verify              # prove the whole chain, exits non-zero
#+end_src

=verify= checks, for every pinned grammar, that the checkout sits on its pin,
that the library exists, that Emacs can load it, that the ABI it reports is the
one the pinned source declares (which is what catches a silent fallback to a
distribution package), and that the font-lock rules bundled with Emacs still
compile against it. The last check matters because a grammar whose node types
have moved on keeps loading, it only loses highlighting behind a warning.

=install= only touches grammars when asked, so the default path stays offline
and takes seconds; without =--grammars= it just says how many are pinned. A
checkout that already carries local edits is never reset by either command.

Which modes use tree-sitter is left to Emacs: =init.el= sets
=treesit-enabled-modes= to =t=, so the whole of Emacs 31's
=treesit-major-mode-remap-alist= (C, C++, CMake, CSS, Dockerfile, JSON, Python,
Bash, YAML, Java, Ruby, TOML, Lua, HTML, JavaScript, TypeScript, C#, PHP, Go
and more) routes to tree-sitter. Note that this has to be =setopt= and not
=setq=, and it has to run after =treesit= is loaded: the variable installs its
value through a =:set= function that fills =major-mode-remap-alist=, and =setq=
skips that function -- the setting would read back as =t= while no ts-mode was
ever enabled. HTML files land in =mhtml-ts-mode=, which is the pair Emacs ships
and which also drives the embedded CSS and JavaScript grammars.

* Docker
The [[file:Dockerfile][Dockerfile]] builds a lean base image (Emacs + git + a C toolchain)
for three distributions; the configuration itself is never baked in, it is
mounted at run time.

| Distribution | Base image         | Emacs package |
|--------------+--------------------+---------------|
| archlinux    | =archlinux:latest= | =emacs=       |
| ubuntu       | =ubuntu:latest=    | =emacs-nox=   |
| alpine       | =alpine:latest=    | =emacs-nox=   |

Arch Linux is the default everywhere.

** dockemacs
=Dockerfile= is driven by =bin/dockemacs=: build an image, run Emacs
interactively, or run the integration test suite inside it.
#+begin_src shell
bin/dockemacs build [DISTRO]                   # build moyue-base:DISTRO
bin/dockemacs run   [DISTRO]                   # run terminal Emacs in that image
bin/dockemacs itest [DISTRO|all] [--rebuild]   # install + test inside the image
bin/dockemacs distros                          # list the supported distributions
#+end_src

=itest= builds =moyue-base:DISTRO= on first use, then mounts the checkout
read-only at =/mnt/emacs.d=, copies it into a writable tmpfs at
=/root/.emacs.d= and runs =moyue install= + =moyue doctor= there, so the
host tree is never modified:
#+begin_src shell
bin/dockemacs itest                # archlinux
bin/dockemacs itest ubuntu
bin/dockemacs itest alpine --rebuild
bin/dockemacs itest all            # every distribution, in order
#+end_src

Extra Docker arguments can be injected through the environment, which is useful
behind a proxy or on a restricted network:
#+begin_src shell
DOCKEMACS_BUILD_ARGS="--network=host" bin/dockemacs build ubuntu
DOCKEMACS_RUN_ARGS="--network=host"   bin/dockemacs run ubuntu
#+end_src

=MOYUE_ITEST_BUILD_ARGS= and =MOYUE_ITEST_RUN_ARGS= are accepted as legacy
aliases for the two variables above.

* Customization
It will automatically create a =~/.emacs.d/.cache/userconfig= file to override
the default settings.

* Environment variables
Emacs started from a desktop launcher or a systemd unit does not inherit the
login-shell environment. =moyue install= therefore captures it once into
=~/.emacs.d/.cache/env.el=, an ordinary Emacs Lisp file:

#+begin_src emacs-lisp
(setenv "PATH" "/usr/local/bin:/usr/bin:/bin")
(setenv "GOPATH" "/home/user/go")
#+end_src

The file is loaded on every Emacs startup. It is only generated when missing,
so manual edits are kept across later =moyue install= runs. Use
=moyue install --force-env= or =M-x moyu/reload-env= to regenerate it from the
shell, and =M-x moyu/env-visit-file= to open it for editing.
